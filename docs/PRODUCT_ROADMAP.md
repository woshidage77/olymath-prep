# 一朵教学｜产品反馈与开发顺序

更新：2026-09-16。依据：维护者查看当前 Demo 后的明确反馈。本文件记录产品方向、功能范围和验收要求；最新技术实施顺序与下一次安排见[AI应用开发排期](APP_DEVELOPMENT_PLAN.md)。后继能力仍为计划，不能视为已经实现或通过教师验证。

## 1. 已确认的调整

- 名称：一朵教学。定位是帮助教师备课的平台。
- 长期目标：逐步支持小学、初中、高中及更广泛的题目。首个切口仍为小学奥数，先围绕五年级家教场景验证。
- 核心价值：服务教学逻辑和题目联系，让老师知道每题为什么选、有什么可讲、怎样接到下一题。
- 已修正原型只包含空间观察题的问题：当前按人教版五年级 15 个单元组织 136 道题，并从题目进入备课链。
- 历届竞赛来源已经建立官方入口清单；再分发许可不明确的试卷不批量复制到公开仓库。拍照识题仍在后继开发队列。
- 代码继续采用 MIT；每项教学内容单独记录来源和使用范围。

长期覆盖范围是产品愿景，不是首版题量承诺。当前范围没有缩成永久的立体图形工具，也不一次扩建全学段题库。

## 2. 一次备课应该怎样发生

1. 教师输入、检索或从照片确认一道起始题，设定学生已有知识与本课目标。
2. 先展示完整题干、条件和问题，明确学生可能卡在哪里。
3. 针对卡点安排概念解释、追问或演示；媒介必须说明解决哪一步理解困难。
4. 回到同一道题，使用刚学的方法解答，并核查结果。演示不能代替回题。
5. 找到有明确联系的下一题：巩固同一方法、比较易混情形、改变条件或迁移情境。
6. 教师编辑顺序与讲解，确认教学包。AI 的候选和教师确认的内容分别保存。

例如原创观察物体题链可以是：给定组合体画出正面图 → 解释遮挡与投影 → 回原题逐列画出 → 比较“正面图相同但搭法不同” → 在给定条件下讨论数量范围。这里只是拟定的教学样例，题面、坐标和答案仍需一起编写与核验。

每题至少回答：为什么选它？要讲哪个方法？学生可能错在哪？本题比上一题多了一步什么思考？不能只按难度从小到大排序，也不能把文字相似当作教学联系。

## 3. 首轮题库契约

当前用 36 道原创题和 100 道 CC BY 4.0 开放数据题验证目录、检索与备课入口。原型读取固定 Python/JSONL 数据；可编辑、可复用版本再进入 PostgreSQL。题库总量不等于每节课的选题数量。

题目保存以下信息：

- 稳定题目 ID、修订 ID、题干、公式、附图及可选几何模型。
- 学段、年级、专题、概念、方法、前置知识，以及带说明的难度标签。
- 答案、分步解法、提示、易错点及人工核验状态。
- 来源、年份与题号（适用时）、许可、可用范围、是否允许模型外发、来源审核状态。

教学编排另存题目修订引用、选题理由、追问、预计时间和题间联系。同一道题在不同课里可以有不同用途。题间联系先支持“前置、同法巩固、对比、迁移”，由教师确认，无须先上图数据库。

首轮检索：关键词加专题、方法、年级筛选；能查看完整题目与来源；区分没有结果和服务失败。先验证中文关键词行为，再根据漏召回情况决定是否加入 embedding。检索结果需要有可解释的匹配信息，不能凭模型虚构题目 ID。

空间工具由题目引用同一份几何坐标和版本，二维投影由坐标计算。图片中被遮挡的方块数或摆法不明确时，保留待确认状态，不能凭识图结果给出唯一模型。

## 4. 拍照识题的边界

首版目标是“单题照片转为可校对的题目，并检索候选”。识别、检索和解题是不同步骤。

流程：单张 JPG/PNG → 教师裁剪到单题 → 校验并解码 → 识别文字/公式与附图区域 → 并排校对原图和结果 → 教师确认 → 原题匹配或相关题检索 → 保存到私有题库。

- 优先印刷题；手写、整本扫描、批量 PDF 和从几何照片自动恢复完整模型延后。
- 识别结果必须可编辑；缺条件、公式不清楚或附图歧义时不能自动定稿。查不到原题时明确显示，只给相关候选。
- 先用合成或获准样本比较本地 OCR 与多模态识别方案，再决定供应商、费用和部署方式。当前尚未选定，也未发生真实照片外发。
- 照片默认私有，不自动进入公开种子库。外部识别调用前显示数据去向并确认使用范围；可以选择手工录入。
- 接入时完成大小/像素限额、真实格式校验、安全解码、元数据清理、私有存储、对象权限、日志去内容与删除机制。路径由服务端生成并验证边界，不能把上传目录直接挂成公开静态资源。
- 原图默认完成校对后删除；保留原图需明确选择。临时文件、失败任务和备份清理规则在接入前确认并测试。

## 5. 产品能力分组

以下P0—P5用于追踪产品范围，编号不再规定技术施工先后。按最新要求，工程顺序采用开发排期A1—A6：Quickstart → LangGraph → RAG → 基本功能补齐 → 前端优化 → 模型评测。

P0｜本轮反馈记录与名称调整。名称、定位、当前能力说明、题库来源核查和本计划落地；不宣称新增业务功能已经完成。

P1｜题目驱动的可检索原型。小型种子题库、筛选与详情、三题教学链、“题目 → 概念 → 原题”的切换。验收重点是每个演示都能追溯到具体题目。

P2｜可编辑且可保存的备课闭环。题库与草稿持久化、题组重排与替换、衔接说明、题目修订与教师审核。开始邀请教师走一次真实备课流程；多人或远程试用前落实身份和对象权限。

P3｜拍照识题。可先收集获准识别样本，与 P1/P2 观察并行；正式上传接口在私有存储与权限边界可用后接入。验收文字、公式、附图歧义、校对、检索和失败恢复，不能只演示识别成功的一张图。

P4｜教学建议、关联题推荐和交付。基于已入库题目生成有引用的备课草稿，教师可编辑；加入讲义导出与最小评测。几何动画或视频按真实教学需求增加。

P5｜扩大题库与受控交付。根据试用证据扩专题、扩学段，核查数据许可，测检索和教学质量，再完善部署、监控与公开发布门禁。

后继只保留能力队列，不排固定多日课程。若实际观察改变优先级，在应用开发排期中统一调整，并保留相同数据与权限条件。暂时无法观察时用原创题推进，不能标为用户验证通过。

## 6. 下一次安排与产品验收

A1—A3 的工程原型现已实现，最新实现边界见[应用开发排期](APP_DEVELOPMENT_PLAN.md)。本人验收仍从 A1 的独立启动和数据流解释开始，再检查 LangGraph 与检索；以下条件作为产品验收，不因 AI 已完成代码而自动通过。

完成条件：

- 能从至少三个预先定义的查询中找到预期候选，能看完整题干、来源及审核状态。
- 三题链每题有选择理由和前后联系；没有结果时不编造题目。
- 起始题、概念演示、回原题引用同一题目修订；切换题目不会沿用上一题的几何数据。
- 所有纳入本次演示的题目均具备来源与答案核验记录；歧义模型不可伪装成已确认。
- 当前实现、测试证据和待教师反馈分开记录。教师是否愿意采用、实际节省多少时间仍待试用。

## 7. 暂未实现与待观察

截至本次记录：五年级 15 个单元文件夹、136 道题的浏览与专题内搜索、题目驱动的三阶段讲解、空间题互动模型，以及本地单用户的草稿编辑/审核/导出已经完成工程原型。单题照片可以安全私有上传、人工校对并检索，但尚未接 OCR。可选模型适配器可以结构化分析题目、进入 Graph 生成备课稿并回答当前题追问；目前只有连接契约测试，没有真实模型效果证据。页面不向教师展示 RAG、流程节点或匹配分数。embedding、登录、多人对象权限、PostgreSQL、OCR 和正式模型评测尚未完成；CMATH 归类、原创题质量和教师是否认可选题仍待逐题复核与试用。

下一次真实备课重点观察：教师从哪里找起始题；为什么淘汰候选；哪些题间联系需要自己补；何时需要图/实物/视频；原题理解和迁移最容易断在哪一步；电脑与手机如何切换。结果用于调整后继队列，不预设答案。
