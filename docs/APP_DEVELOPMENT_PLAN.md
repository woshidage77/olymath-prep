## 本人验收入口：仍从 A1 Quickstart 开始，预算 4.5 小时

核心交付：本人能独立启动项目，并跑通“选择一道真实有题干的原创样例 → 查看概念讲解 → 回到该题 → 查看下一道关联题”。先用三道经过核验的原创题与确定性返回，所有结果显式标为演示。

现有 Vue、FastAPI 和空间模型可复用，不重建脚手架。已有技术演示运行证据不等于本人独立启动、题目流程或学习验收已完成。

1. 30 分钟：按 README 独立启动前后端，定位浏览器请求、接口和返回字段。
2. 60 分钟：确定三题链；整理题干、答案、来源、教学作用和必要几何坐标，核对题目与模型一致。
3. 75 分钟：明确题目与备课返回结构，让接口按选中题目返回对应讲解和关联题；暂用固定数据。
4. 60 分钟：在现有页面展示完整题干、概念讲解、回原题和关联题入口，保留必要的失败提示。
5. 45 分钟：验证切题不串数据、缺失题目有明确提示；运行适用的编译/测试/构建，记录本人可独立完成的部分。

完成判断：能现场跑通一条题目教学链，并解释“页面输入如何传到后端，题目 ID 如何决定结果”。时间不足时保住一条链，暂不扩题量；完成后可推进一个直接后继。后续不排固定日期，不要求一天做完一个阶段。

## A1｜Quickstart：跑通一道题的完整路径

应用成果：三题演示链；题目、讲解、几何工具和回题环节绑定，能独立启动和定位请求错误。

核心知识：FastAPI 路由、请求/响应结构、Pydantic 校验、前后端调用、环境配置和错误状态。

工程重点：先定义题目 ID、修订和来源；固定数据与真实能力明确区分。第三方教材不进入公开样例；不需要模型密钥即可体验。

阶段验收：工程侧已实现三题选择、题目详情、三阶段回题、关联题入口及未知题目错误契约；编译、9项后端测试和前端构建通过。本人仍需按顶部安排独立启动并解释数据流，之后才算学习验收完成。

## A2｜LangGraph：把备课步骤组织成工作流

应用成果：把“校验需求 → 取得候选 → 编排题组 → 生成讲解草稿 → 校验引用 → 等待教师确认”组织成可追踪流程。暂用固定候选与 Mock 生成器，A3 再替换检索实现。

核心知识：State、node、edge、条件分支、结构化输出、人工确认与状态保存。LangGraph 负责流程；LangChain 仅按需提供模型或检索组件，不要求先学完另一套框架。

工程重点：业务题目和修订 ID 贯穿节点；无候选、输入不合法与生成失败有不同处理；教师改动后旧结果不能覆盖新内容。内存状态只能证明单进程行为，持久化恢复与业务存储在 A4 补齐并验证。

阶段验收：相同输入下 Mock 可复现；成功、无候选、非法输出均走到预期状态；未经教师确认不会标为已批准；可替换生成器而不改业务流程。

工程记录：已实现6节点 StateGraph、三处条件分支和可序列化状态；成功、无候选、非法输入及跨题引用失败均有回归。页面展示执行轨迹并停在 `waiting_teacher_review`。当前等待状态不是可恢复 interrupt，详细边界见 [A2实现说明](A2_LANGGRAPH_NOTES.md)。本人掌握仍待独立讲解与修改验证。

选择依据：LangGraph 官方说明其可混合确定性步骤与模型步骤，也可独立于 LangChain 使用。因此本项目先以流程编排为主，不需要预先搭建自由行动的 Agent。[官方概览](https://docs.langchain.com/oss/python/langgraph/overview)

## A3｜RAG：让备课草稿引用题库与教学资料

应用成果：建立可检索的种子题库，把检索结果作为讲解与编排的依据。先扩到 8—12 道核验种子题，再按需要扩到同专题 20—30 道；数量只是试验规模。

核心知识：文档与题目结构、metadata、embedding、向量索引、retriever、Top-K、上下文组织和来源引用。

实现顺序：

1. 先做关键词和标签基线；保留完整题目，避免机械切片拆掉条件或让答案与题干失联。
2. 按用途区分题目内容与教学方法资料。长资料可切片，但必须能回到来源和修订。
3. 接入一种固定的 embedding 实现做语义检索实验，记录模型/维度/索引版本；与关键词基线比较，收益不足则不默认启用。若尚未接入真实 embedding，只能标为接口准备完成。
4. 返回有真实题目 ID、可见范围与匹配信息的候选，再构造带引用的上下文交给 A2 生成节点。

工程重点：按用户可见范围检索；区分没查到与检索服务失败；无依据时不补造来源；索引能重建且不会重复导入。初期小索引可在本地验证，持久化阶段沿用 PostgreSQL，确认收益后再决定 pgvector，不同时维护多套向量库。

阶段验收：固定少量查询能找到预期题目，条件/来源没有丢失；空结果和服务失败可区分；生成上下文能追溯。前期使用 Mock 生成器时，交付名称是“检索与 RAG 链路”，不能宣称真实生成质量已经验证。

RAG 中的检索与生成需要分别验证：题库检索本身不等于完整 RAG。这里先做好检索和上下文组织，真实生成及教学效果在 A6 验证。[官方检索说明](https://docs.langchain.com/oss/python/deepagents/retrieval)

工程记录：题库现按人教版五年级上下册 15 个单元组织，共 136 道题，包括 36 道原创题和 100 道 CC BY 4.0 的 CMATH 五年级题。加入 LangChain Document、关键词/标签检索、搜索 API、空结果语义、带修订 ID 的上下文，以及 LangGraph `retrieve_context` 节点。23 项后端测试覆盖目录计数、专题过滤、排序、错误边界、文本题与空间题不变量。教师页面只展示课程目录、题目和教学建议，不展示内部工作流、RAG 或匹配分数。embedding 按既定顺序留到模型统一评测，详细见 [A3实现说明](A3_RAG_NOTES.md)。本人掌握、逐题归类审核与教师检索评价仍待验收。

## A4｜补齐基本功能：让备课可以保存、修改和复用

应用成果：持久化题库与备课草稿，支持题目替换、重排、讲解编辑、审核和基本讲义导出；接入单题拍照入口。

核心知识：PostgreSQL、数据迁移、题目修订、对象权限、文件处理、服务适配器和必要的后台任务。

工程重点：先保存教师改动，再考虑自动推荐；已审核版本不被覆盖。照片走“上传 → 识别 → 校对 → 检索 → 私有保存”，具体数据边界沿用产品计划。选择一种 OCR 实现先做必要连通验证，正式效果评测留到 A6；只有上传或 Mock 文本时不能把拍照识题标为可用。

阶段验收：刷新或重启后数据仍可用；替换题目会刷新受影响的讲解与审核状态；教师版与学生版输出有区别；私有图片不公开、不可越权访问，能删除。先完成必要权限，再进行多人或远程试用。后台队列仅在耗时任务确有需要时引入。

工程记录：已完成本地单用户 MVP。SQLite 保存草稿及乐观版本，支持同课题增题、移除、重排、追问/讲解编辑、审核、删除和教师/学生 Markdown 导出；照片经格式、大小、像素、安全解码、重编码与路径边界检查后进入不公开的私有目录，可人工校对文字并检索题库。按最新用户要求提前接入可选 OpenAI Responses 适配器：模型以结构化输出识别知识点、题型、难点、易错点和变式，LangGraph 增加可选分析节点并把结果写入三阶段备课稿，页面提供当前题问答。没有密钥时明确降级到基础备课，AI 接口返回 503。31 项后端测试、前端类型检查和生产构建已通过；真实模型尚未调用和评测。SQLite 不替代计划中的 PostgreSQL，多人对象权限与 OCR 仍未完成。详细见 [A4实现说明](A4_BASIC_FEATURES.md)。

## A5｜前端优化：把功能组织成老师顺手的备课工作台

应用成果：集中完善“题库检索 → 题目详情 → 题组编排 → 教学讲解/媒介 → 讲义预览”的使用体验。

核心知识：Vue 状态管理、异步反馈、表单与公式展示、组件边界、响应式布局和可访问性。

工程重点：当前题目、关联题和教学理由清晰可见；加载、无结果、错误、未保存和待审核状态明确。空间模型只在该题需要时展示，并与题目数据绑定；先保证主要操作可用，再处理视觉、性能与移动端适配。

阶段验收：用 Mock 与已确认数据走完一次备课，教师能找到起始题、编辑三题链并导出；主要异常能恢复。记录操作困惑，不把模型措辞当成界面可用性的证据。

工程记录（2026-09-17）：已增加独立品牌入口页，进入后按年级、册别和单元选择专题；专题卡片改用简洁序号，不再显示文件夹图标。每个专题把一题通用基础题设为“推荐起点”并置顶，其他题按基础、进阶、挑战排序，支持专题内直接筛选难度。100 道开放题已由编号标题改为四字题型名，并修正一批间隔、方程、因倍数、体积和除法的明显错分；关联题检索改为优先使用当前题标题和题干，使“接下来可以讲什么”更贴近当前题型。页面采用克制的深绿、米白和金色体系，并完成桌面端入口、专题列表、筛选与关联题的浏览器交互检查。

工程回归为 35 项后端测试、Python 编译检查和前端生产构建通过。当前结果是作品集可展示的工程版本，不代表教师可用性已经验收；100 道 CMATH 仍需教师逐题复核，移动端、键盘可访问性、真实教师任务测试和模型评测继续留在 A5/A6。

## A6｜模型评测与迭代：基本功能完成后集中进行

进入条件：A1—A5 的业务结构和主要功能可运行；当前模型适配器与无密钥基础路径已分离，待用固定评测集进行真实调用；来源与外发边界可执行。保留 Fake 客户端作为连接契约回归，并保留无密钥基础备课路径。

应用成果：先接通一个基线模型，再在同一评测集、输入和预算下比较候选；选定配置后回归完整备课流程。评测会暴露上游问题，允许返回对应阶段修正。

核心知识：结构化输出、提示词版本、评测样例、人工评价、延迟/费用、超时重试及故障归因。

分别记录：

- 检索：教师认可的候选是否被找到，是否违反年级或方法约束。
- 生成：题意理解、数学正确性、题目引用、适龄方法、追问价值和题间衔接。
- 识图：文字/公式/条件完整性、图形歧义和教师校对成本，不用一次识别成功代表整体效果。
- 工程：格式合法率、超时、延迟、用量及成本；错误是否可恢复。
- 产品：教师是否愿意采用、修改多少、从找题到可用讲义实际耗时多少。

起步用一小组已核验的典型与失败样例；保留未参与调参的题，避免只记住演示答案。模型判断可作辅助，数学与教学评价必须由可复核计算或人工评审支撑。保留失败例和分母，不承诺预先设定的高准确率。

阶段验收：形成基线报告、失败分类和下一轮优先改进项；没有外部调用与实际评审证据时，不写“模型已通过”。公开发布、运行监控与更广学段扩展仍需后续交付门禁。

- 每个阶段只有一个主要应用成果，达到验收条件再推进；不因安装了框架就判定完成。
